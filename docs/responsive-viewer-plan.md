# 画像ビューア再設計・実装計画

Rust + egui / 単体exeを維持して閲覧フローを改善する。関連付けの既存修正を保持する。

## 状況
実装済み。#7（基礎と関連付け）、#9（非同期読み込み・メモリ制限・GIF・画像中心UI）、
#10（詳細表示の別スレッド化・LRU・失敗の再試行）、#11（応答速度の計測テスト）で `main` に入っている。
以下の各項目は設計時の要件で、検証は cargo test / clippy / fmt と、実機での表示・移動・回転・
サムネイル一覧・GIF・ホイール・パンの確認で行った。計測方法は README の「Latency benchmark」を参照。

## 1. 非同期読み込み（P1）
- 現在画像・先読み・高精細表示をワーカーで処理し、UIで画像をデコードしない。
- 現在画像を先読みより優先し、待機要求をまとめる。選択世代で古い結果を破棄する。
- 読み込み中/失敗を表示し、連続移動・回転・空フォルダの操作を維持する。
- 検証: 待機中に別画像へ移動、古い結果の拒否、破損画像からの復帰。

## 2. メモリと表示品質（P1）
- 静止画キャッシュをバイト上限付き（80MiB・LRU）にする。デコードにも上限を設ける。
- 原寸表示は可視領域だけを非同期に切り出し、全画像分のGPUタイルを保持しない。
- GIFを小さい有界キューで順次再生し、200フレーム切り捨てと全フレームGPU保持を廃止する。
- 検証: キャッシュ上限、回転後の原寸領域、200フレーム超GIFの末尾とループ、キャンセル。

## 3. 操作と画面（P2）
- ホイール移動・中ボタン押下中の2倍拡大・カーソル追従を既定として保持する。
- 操作設定を一つの設定画面に集約する。
- ツールバーを自動非表示にし、上端ホバー/Tabで再表示。状態表示を簡潔にする。
- 開閉式のサムネイル一覧を追加し、表示行のみ非同期に取得する。
- 検証: 合成入力による操作、一覧選択、設定切替、読み込み/空/失敗画面。

## 4. 責務分離と全体検証
- ファイル一覧・画像処理・読み込み/キャッシュ・入力・描画・Windows関連付けを分離する。
- 既存の日本語フォント、自然順ソート、関連付け回帰テストを保持する。
- cargo fmt --check / cargo test / cargo clippy / release build / 関連付けスクリプトテスト。
- ネイティブ実画面検証は環境が許す範囲で行い、未検証事項はPRに明記する。

## 限界
- 汎用画像デコーダーは領域だけのデコードに対応していないため、原寸領域の生成時は原画像をワーカーで一時展開する。デコード上限超過は明示的なエラーにする。
- 実行中のデコーダーを強制停止せず、完了時に世代を確認して破棄する。
- 原寸領域のデコードは専用スレッドで行うため画像移動は待たされないが、原画像全体を展開する。展開結果（最大128MiB）は同じ画像・同じ回転の間だけ保持して再利用し、別ファイルへの移動・回転・ファイル更新で破棄する。
- 中ボタンは「押している間だけ2倍に拡大」で、素早く押して離してもフィット⇔原寸の切り替えは行わない（仕様）。
- 計測は読み込み完了までで、描画・テクスチャのアップロードは含まない。
